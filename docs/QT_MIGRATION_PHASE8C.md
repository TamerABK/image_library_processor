# Phase 8C: Trash review

Trash is a project-scoped review workflow, not an analysis stage. `TrashController` reads the current discovered `PhotoListModel`, persisted Blur `image_decisions`, and valid current duplicate-group `member_intents`. Only explicit `REMOVE` decisions create candidates. A photo with both sources appears once. The sidebar count includes current candidates, including blocked ones, and excludes paths absent from discovery.

`TrashPhotoModel` provides a virtualized `PhotoGrid` and a virtualized decision list. Its selection is only for the current execution batch; it does not change Library selection or persistent review intent. Filters are All, Ready to remove, and Needs attention. Blur `KEEP`/`REVIEW` versus duplicate `REMOVE`, duplicate `KEEP` versus Blur `REMOVE`, Favorites, changed revisions, and unavailable review metadata block execution. A Favorite must be unfavorited or its removal canceled first. No recommendation by itself enters Trash.

**Cancel removal** clears all current `REMOVE` sources for one photo. Blur becomes `UNDECIDED` with `selected_for_deletion=false`, preserving unrelated image-decision columns. Each duplicate `REMOVE` is cleared while keeper paths and other member intents remain; its group becomes unreviewed. The source file is untouched. The duplicate controller reloads its saved review, and the Trash projection updates without analysis.

The user selects ready photos and confirms a dialog with photo count, total size, and source breakdown. `TrashController` snapshots the folder, generation, paths, reasons, and revisions. One bounded worker checks each file's existence and size/mtime immediately before calling `send2trash` sequentially. Room 36 moves files to the operating-system Trash using `send2trash`. It does not permanently unlink source photos. Missing or changed files fail safely; other batch members continue. Each confirmed batch appends succeeded and failed paths to the existing deletion transaction tables. A history-write failure is reported separately and never retries a successful physical move.

After any successful move, the controller closes the Inspector, removes the moved identities from the master Library model, and reopens the current project once. Project discovery invalidates the old processing session and refreshes Library, Blur, duplicates, People, Favorites, and Trash. If the user switches projects while an already-confirmed batch runs, that batch finishes for its original folder, but its result cannot populate the new project's UI. Favorite metadata is not rewritten by Trash and may remain as an inactive row for an absent path. Deletion history is append-only; Blur review writes update their own photo rows without rewriting transaction history or duplicate metadata.

Current limitations: Room 36 does not provide its own physical deletion undo or a transaction-history browser. OS Trash recovery is external. Execution is blocked while Favorites or duplicate review state is loading or unavailable, because those choices cannot then be reconciled safely.
